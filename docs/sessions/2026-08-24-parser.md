# 2026-08-24 (second session) — S1 migration to `churnkit`, then S3: the parser

Two files carry today's date because two sessions ran. The earlier one is S2,
the fixture corpus; this one is the layout migration the S2 note left open,
followed by the parser those fixtures were built to judge.

## What changed

**The open decision from the S2 note is answered: migrate.** Dhruv chose the
`churnkit` layout, so the whole tree moved in one change rather than leaving new
platform code at S-plan paths and old code at its own import root:

- `pyproject.toml` — package `churnkit`, src layout, Python 3.11+, setuptools
  backend. It is now the only dependency declaration; `requirements.txt` and
  `requirements-ui.txt` are deleted. Dependencies are split into extras
  (`ml`, `serving`, `ui`, `cli`, `dev`) instead of one flat list.
- Everything moved under `src/churnkit/`. The Telco implementation is
  quarantined in `src/churnkit/reference/`, and `tests/test_layout_guards.py`
  fails if a Telco column name, category value or the dataset's name appears in
  any platform module (I11).
- Imports, `app/streamlit_app.py`, both Dockerfiles, the Makefile, CI and the
  README/ROADMAP paths were all updated in the same commit. Nothing still
  imports `src.*`.
- CI now runs ruff, mypy (strict, `churnkit.reference.*` exempt), the suite, and
  a coverage gate of 80% on the platform packages.
- ADR 0003 records the layout, the quarantine, and both deliberate deviations
  from S1 as written.

**S3, the parser**, in `src/churnkit/ingest/reader.py`, written against the S2
manifest: encoding sniffing (including cp1252 versus latin-1, which disagree in
exactly the byte range Excel-on-Windows uses), delimiter detection by field-count
consistency rather than character frequency, header-row detection below export
banners, per-column date-order inference, Excel serials, per-column null tokens,
currency and percent notation, duplicate and ghost columns, ragged rows reported
by line number. `ParseResult` carries the frame plus every decision made.

## Verified, not assumed

The tests were written first and observed failing — first as a collection error
with no module to import, then, after the guards were added, with only the
"reader.py must exist" guard red. 114 tests pass now; `ruff` and `mypy --strict`
are clean; `churnkit/ingest` is at 90% coverage.

Passing 78 fixture tests on the first run was not treated as success. Running
the parser over the corpus by hand and reading the output against the manifest
found nothing, but probing it with files the corpus does not contain found a
real defect: **`1,5` in a semicolon-delimited file parsed as `15.0`**. A comma
was being stripped as digit grouping everywhere, which is the same tenfold class
of error the manifest bans for percent signs, and no fixture covers European
decimal commas. The decimal separator is now decided per column from evidence —
the same discipline the date order already had — and reported in the column
stats. Two smaller findings from the same probing: failures were reported at the
line a record *ended* on rather than where it starts, which is wrong for a
quoted value containing a newline, and a header with no rows under it produced a
silently empty frame. Both are fixed and covered.

Note on discipline: three of those four repairs had their test written first and
watched fail. The fourth (`test_a_wrapped_row_is_reported_at_the_line_it_starts_on`)
was written after the fix, so it verifies rather than drives — it is the one
assertion in this session that did not earn its keep the honest way.

**A second defect surfaced, this one pre-existing.** Building both container
images as a check found that the API image does not build: `xgboost-cpu==3.4.1`
publishes no wheel for Python 3.11, and both Dockerfiles and CI pinned 3.11.
The deleted `requirements.txt` carried the same pin, so the API image build and
the CI Docker job have been failing since that version was pinned — moving the
dependency declaration into `pyproject.toml` is only what made it visible. The
floor is now 3.12 everywhere, which is what the development virtualenv already
runs. Both images build and the UI image was checked to contain no model
library at all: `sklearn`, `mlflow`, `xgboost`, `shap` and `fastapi` are all
absent from it, so the portal cannot become a second inference path.

## Half-done / next

Nothing half-done. Next is **S4 — schema inference and leakage detection**,
which reads a `ParseResult` and proposes roles, a target, an ID and a timestamp
column, and which must block on a planted leak. The S4 prompt asks for the
thresholds and false-positive reasoning to be explained before implementing.

Two things S4 should carry forward from here:

- `ParseResult.requires_disambiguation` is True while a column is flagged
  ambiguous. Nothing enforces that a caller respects it yet; S4 or S7 should
  make training refuse on it, which is the same shape as the I7 confirmation
  gate.
- Column `kind` here is deliberately coarse (numeric / datetime / text). Role
  inference — identifier, low- versus high-cardinality categorical, target
  candidate — is S4's job and should not leak back into the reader.

## Invariants touched

- **I10** throughout: every parse failure names its column and shows sample raw
  values, and every unreadable row is reported with its line number and the raw
  line.
- **I11**: enforced by a test rather than a promise for the first time.
- **I7** in spirit: ambiguous dates are flagged rather than guessed, and the
  `dayfirst` override is how a human answers.
- **I8**: every expected value in the new tests was computed from the fixtures,
  and the two manifest claims checked during S2 still hold.

## Invariants I was tempted to bend

Two, both in the same direction — making the parser look more capable than it
is.

The first was to guess ambiguous dates using the locale, since `03/04/2024` is
day-first in most of the world and the fixture would then parse cleanly. That is
exactly the silent, undetectable corruption the manifest describes, and the flag
costs one confirmation click.

The second was more tempting because it was invisible: after finding the decimal
comma bug, the quick fix was to special-case semicolon-delimited files as
European. That would have been a guess dressed as a rule — plenty of exports use
semicolons with decimal points — so the evidence test is per column instead, and
it says so in a warning when it fires.

One more worth recording: the guard test flagged the word "Telco" in two comments
I had just written in platform modules. The prose was harmless, but the fix was
to reword the comments rather than to soften the guard.
