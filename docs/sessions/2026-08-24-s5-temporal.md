# 2026-08-24 — S5: temporal validation

## What changed

`src/churnkit/validation/temporal.py`, built test-first. 189 tests → 231 plus
one skip. 92% coverage on the new module, 92% across `ingest/` and
`validation/` together.

Four functions, as S5 specified: `cutoff_split`, `walk_forward_folds`,
`label_with_censoring`, `assert_no_time_travel`. Plus the structural guard S5
asked for by name. ADR 0006 has the design reasoning.

The module is pure pandas — no scikit-learn — so `validation/` stays in the core
dependency set rather than pulling the `ml` extra into every install.

## The number that justifies the module

On a synthetic dataset where the churn driver drifts over time:

| Split | AUC |
| --- | --- |
| Random (what every churn tutorial reports) | **0.759** |
| Temporal (what is actually true) | **0.521** |

A 0.238 overstatement, on a model that is barely better than a coin flip. This
is asserted in `test_a_random_split_flatters_the_model`, so the claim is
executable rather than rhetorical. Walk-forward folds on the same data run
0.603 / 0.591 / 0.689 / 0.700 across an expanding training window.

## The guard found a real violation immediately

`churnkit/reference/train.py` calls `train_test_split(X, y, test_size=0.2,
stratify=y, random_state=42)` — CLAUDE.md's first poisoned default, verbatim,
including the 42.

It is **allow-listed, not fixed**, because the Telco reference dataset genuinely
has no time column and I1 permits a random split in that case. The allow-list
entry is named and commented so the exception is visible rather than silent.

**Open finding, not addressed this session.** I1 also requires that a dataset
with no time column be *marked optimistic* in the report. `train.py` does not do
this — there is no such marking in its logged metrics, and the PR-AUC 0.658
quoted in `ROADMAP.md` is therefore an unmarked random-split number. Fixing it
means editing `reference/`, outside S5's stated scope, so it is written down in
ADR 0006 rather than done quietly. **This needs a decision before any model card
is published.**

## An invariant I was tempted to bend

The guard I had just written failed on `temporal.py` itself, because the module
docstring explains why it never calls `train_test_split` — and the guard matched
the words. The quick fix was to reword my own docstring and move on.

Instead the guard now strips comments *and string literals* with `ast` before
matching, so it detects calls rather than mentions. That is what the existing
`BANNED_IN_INGEST` guard already claimed to do in its comment ("prose about the
ban is fine; calling the thing is not") but achieved only for `#` comments. The
new guard does it properly. I did not retrofit the older guard — out of scope,
and it currently passes — but it has the same blind spot and should be moved to
`_executable_source` when something next touches it.

I also verified the guard has teeth rather than trusting that it passed: I
planted `from sklearn.model_selection import train_test_split` into
`temporal.py`, confirmed the suite went red, and restored the file. A guard that
has never been seen to fail is not known to work.

## Two of my own tests were wrong

`test_too_few_folds_for_the_data_is_refused_with_the_numbers` asked for 40 folds
of 1 day against 720 days of history — which is entirely satisfiable, so nothing
raised. Rewritten to 40 folds of 60 days, which genuinely needs 2400 days, and
the assertion now checks that number appears in the message.

The labelling fixture also needed care: the censoring test only proves anything
if `data_end` falls *before* the horizon closes, which is a different scenario
from the same customer being observed throughout. Both cases are now separate
tests, and `test_censoring_is_never_silently_folded_into_the_negative_class`
asserts the negative count actually differs between them.
